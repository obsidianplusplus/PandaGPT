# PandaGPT 2.1.1 性能说明

目标是使世界采样的工作量有界，并在服务器忙碌时退让。不能通过静态代码或模拟测试保证所有服务器绝对不卡顿；硬件、玩家视距、农场密度、其他插件与资源包复杂度都会影响结果。

## 主线程工作与退让

| 路径 | 处理方式 | 仍需注意 |
|---|---|---|
| 图像射线 | 逐格检查截止时间，DDA 游标跨 tick 续跑；每任务最多 32 格后轮换 | 单格内部原生碰撞 API 不能抢占 |
| 图像、局部调查、标记、后台检查 | 共用截止时间和格子上限，预算不随玩家人数相乘 | 2 ms 是软预算；任务检查和一次 API 调用可能超出 |
| 重复方块访问 | 同 tick 缓存 Block、材质、表面状态/颜色/染色和区块可访问性；下 tick 清空 | 不跨 tick 缓存动态世界状态；命中面邻格光照可能额外读一个格子 |
| 负载上升 | 每 20 tick 读取平均 tick 时间；达到 45 ms 后暂停后台、前台预算降至 1/4 | 阈值针对常规 20 TPS；修改服务器 tick rate 时需重新评估 |
| 恢复 | 连续五次检查低于 35 ms 才恢复后台 | 避免阈值附近频繁开关；恢复不会突发补齐欠下的观察 |
| 在线玩家轮转 | 加入/退出维护 UUID 名单，每 5 tick 最多检查一人 | 多人时目标刷新会延后；不会随在线人数增加检查量 |
| 目标与配方 | 按产物索引；材料谓词按不同 choice/背包槽预计算；递归仅查布尔表 | 每次分配最多 1024 个节点；时间不够时不给“材料已齐”的肯定结论 |
| 方块变化 | 地点精确坐标索引，画面按世界/区块筛选；合并同玩家失效写入 | 同位置被多玩家记住时仍需分别失效；观察最多 2048 个已命中坐标 |
| 地点读取 | 无变化时复用不可变快照；文件读写在单个有界 I/O worker | 队列/磁盘故障会记录错误，损坏文件仍禁止覆盖 |
| 日志 | 单 worker、256 条队列，每条至多 32768 字符；满队列丢弃新增记录 | 这不是可靠审计队列；丢弃数在管理员 status 中显示 |
| 图像/材质 | 单 worker、有界队列；4096 个纹理状态及 8192 个坐标变体 LRU 缓存 | PNG 解码像素预算仍默认 64 MiB；Java 对象/索引/模型还会额外占内存 |
| 普通提问 | 模型队列满时先拒绝世界上下文采集；会话过期清理最多每 30 秒扫描一次 | 回调和显式命令不在视觉调度循环的计时中 |

时间或格子耗尽时，未完成射线保留游标；不会把剩余部分当作可见天空。仍只读取已发送且加载中的区块，不请求远处区块加载。采样期间收到范围内改块事件会取消任务，包括正在穿过空气的射线，避免暂停前的空格状态被当成当前证据。

实体查询从创建任务时移至采样末段，使用原生 predicate 限制返回候选，属性快照最多处理 256 个，并检查剩余时间。**原生空间查询自身仍可能枚举大量实体，无法被插件截止时间中断。** 高密度农场需要真实剖析；降低 entity_radius 或关闭自动 perception 可以减少调用机会。负载退让时前台画面可省略实体快照，背景观察暂停；空实体列表始终不证明附近没有实体。位置与方块样本本身仍为分 tick 观察，不是全世界原子快照。

## 可复现的访问次数对比

基线为提交 `1a3751d8b60d92ae81dfaabbf7aca91d3b3aa892`。脚本通过 git 读取并编译该提交的 **实际 BlockRaycaster/VoxelMarcher**，与当前版本比较。World/Block 使用模拟对象，不运行 Paper，不估算 TPS，也不对墙钟时间作性能断言。

| 场景：256 条、96 格、全空气且区块已发送/加载 | 旧版方块读取 | 新版方块读取 | 旧版区块检查 | 新版区块检查 |
|---|---:|---:|---:|---:|
| 16×16、FOV 70° 的透视射线 | 34,412 | 30,544 | 34,412 | 34 |
| 同一方向重复射线，体现缓存高度重叠的情况 | 24,832 | 97 | 24,832 | 7 |

透视场景减少约 **11.2%** 的方块读取；第二行是理想重叠场景，不能用来宣传所有场景都减少 99.6%。等工作量比较临时放宽了格子预算。使用默认 8192 格预算时，同方向长射线在这一 tick 完成 84 条，第 85 条暂停；时间预算可能使实际完成量更少。时间隔离和访问上限是本次优化的主要收益，不是增加每 tick 的吞吐。

结果保存在 [performance-results.json](performance-results.json)。CI 中的 `target/performance-results.json` 是当前版本工作量验证，随 JAR 一起上传。

复现基线比较（需要 Java 25、Maven、完整 git 历史及一次测试生成的 classpath）：

```bash
mvn -B -ntp test
python3 tools/benchmark_performance.py
```

可指定 `--baseline <提交SHA>`、`--maven <mvn路径>`、`--repo-local <缓存目录>` 和 `--offline`。基线脚本只比较指定两份源文件的世界访问次数，不代表整个插件的端到端性能。

回归检查还覆盖逐格暂停后的负坐标/边界/角点一致性、跨 tick 缓存清空、截止时间先于世界访问、全服额度、压力恢复滞后、禁止为拒绝请求采集上下文、权限恢复后的轮转、索引替换/世界隔离/淘汰，以及 I/O worker 被阻塞时一万次方块失效不会塞满队列。真实 Mojang PNG 测试继续验证模型、UV、染色、透明度和遮挡。

## 保守配置

较弱机器或繁忙服务器可以先使用以下配置。修改后运行 `/pandaadmin reload`。插件自动下载的官方材质完成后会立即生效；手动放入的资源包需要重载，资源可用性不在每次采样或 status 中访问磁盘。

```yaml
panda:
  perception:
    observe_seconds: 60
    entity_radius: 12
    max_entities: 8
  vision:
    width: 96
    height: 54
    max_distance: 48
    rays_per_tick: 128
    cells_per_tick: 4096
    time_budget_ms: 1
    max_concurrent_captures: 1
    max_debug_particles: 12
    save_images: false
```

尺寸、距离、预算应一起降低。只减小预算而保持大图和远距离，可能经常触发 200 tick 超时。暂停后台不会改变普通提醒的去重和频率约束，也不会补发过期建议。

## 真实服务器验收

先记录关闭 perception/vision 的基线，再在相同 Paper 26.3、Java 25、世界、视距与在线人数下开启。分别测试闲置、两人同时手动捕获、多人低频观察、长距离空气/复杂半砖、密集生物农场、红石持续变化、较大资源包冷启动，以及故意增加整服负载后的退让和恢复。

使用 Paper 官方推荐的剖析命令，在问题正在发生时执行：

```text
/spark profiler start --timeout 600
```

对比整服 MSPT 的 p50/p95/p99/最大值、GC 停顿、主线程 PandaGPT 调用占比、World.getNearbyEntities/Block.rayTrace/getCollisionShape、worker CPU、队列、内存和捕获完成/取消率。管理员 status 中的 loop_p95_ms 是最近 512 次 **计划循环（含闲置）** 的 p95；loop_max_ms 是该控制器运行期间最大值，不能代替整服指标或事件/模型回调耗时。block_reads/cache_hits 统计图像射线，不包含调查或粒子复核的额外读取。

建议验收目标：在相同场景下没有新增持续的超 50 ms tick，PandaGPT 的计划循环 p95 接近配置预算，超时峰值能在 spark 中找到具体来源，后台负载退让确实生效。该目标需实测确认，当前尚未进行真实 Paper 服务器或付费模型联调。
