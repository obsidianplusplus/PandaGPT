# 🧠 游戏记忆与记忆蒸馏

游戏记忆和记忆蒸馏遵循同一个标准：**玩家真正需要的时候，找回正确的那件事。**

玩家只需要在聊天开头说 `panda`。服务器记录死亡和成就事件；玩家明确要求保存的经历、偏好、计划和经验，以及已有地点、笔记和当前目标，都能按需检索。记忆按玩家 UUID 隔离，保存到 `memory/<UUID>.json`，重启后仍然可用。

## 你可以这样说

```text
<Steve> panda 记住，以后我喜欢中式建筑
[Panda] 记住了，以后设计时会参考中式风格。

<Steve> panda 记一下，下界采矿计划是先找石英，再挖远古残骸
[Panda] 记住这项计划了。

<Steve> panda 上次我为什么死了？
[Panda] 当时你掉进了岩浆，地点在下界……

<Steve> panda 下界采矿计划已经完成了
[Panda] 已记为完成。

<Steve> panda 帮我整理记忆
[Panda] 已整理游戏经历、事实、计划和经验，并保留原始记录。

<Steve> panda 忘掉我的建筑风格偏好
[Panda] 将删除这项偏好及其旧版本。请发送“确认遗忘 <工具生成的UUID>”确认。

<Steve> panda 确认遗忘 <工具生成的UUID>
[Panda] 已忘掉这些记录。
```

上面的回答是示意，实际回答必须以工具返回的记录为依据。若找不到匹配记录，Panda 应明确说明没有可靠记忆；若多条记录仍无法确定指代，应先澄清。

## 独立索引与语义蒸馏

| 流程 | 处理内容 | 保留规则 |
|---|---|---|
| 游戏事件 `episodes` | 死亡、成就、玩家要求保存的具体经历 | 保留各次发生的事件与时间，不把一次事件推断为持久偏好 |
| 事实与偏好 `facts` | 明确偏好、地点及其他事实 | 同一主题、同一世界取最新证据，旧版本可在历史查询中回溯 |
| 计划 `plans` | 待办、当前合成目标、玩家明确的计划 | 完成或取消记录会阻止旧计划重新作为待办召回 |
| 经验 `lessons` | 玩家明确总结的经验 | 同主题保留最新版本，不由助手自行推测教训 |

四类索引负责去重、版本选择与检索，各有容量预算。独立的后台模型直接读取完整原始证据，生成最多 32 条语义摘要及 64 条经历关系。关系包括延续、同一项目、对比、计划结果、经历启发计划、经验来源和可能因果。例如，“掉进岩浆丢装备”和“下次先准备抗火药水”可以建立有解释的经历与计划关系。摘要和关系保留证据 ID，属于模型解释；可能因果不能作为已验证原因，也不能据此推断玩家情绪。

证据变化后自动排队，同一玩家请求合并，快照过期后重新处理最新证据。全局最多一个语义任务运行、32 个任务排队。每次最多读取各类最近 12 条、合计 24,000 字符的完整证据，不截取长原文，也不将旧摘要作为下一轮证据。开启后会增加配置模型服务商的请求和费用。模型失败或输出不合法时，原始证据与已提交解释保留；玩家可以重试。提交时检查证据快照、模块开关与模型实例，过期结果不会写回。

每类最多保留 96 条原始证据，每个流程最多输出 24 条蒸馏索引。高频事件不会挤占其他类别的配额。检索也会查找原始证据，因此较旧、未进入蒸馏索引但仍在保留范围内的事件仍可被找到；容量上限之外的历史会被淘汰。

## 如何找回正确的那件事

1. 用玩家当前需求的具体关键词检索，支持英文词和中文二元词组。
2. 默认只检索当前世界及跨世界的个人记忆；明确查询其他世界时才扩大范围。
3. 按相关程度排序，时间只用于同分排序，不用最近记录替代真正相关的记录。
4. 返回原始证据、来源、记录时间、世界、位置、流程和状态；蒸馏索引保留证据 ID。
5. 更新后的旧版本、过期事实、已完成计划默认不召回；历史查询可以查看它们。
6. 地点发生变化时标为 `needs_verification`。历史死亡掉落物也只能证明当时掉了什么，不能证明现在还在。

每次提问最多自动附带 3 条与本次需求有关的记忆，并受字符预算限制。完整证据通过 `recall_game_memory` 工具按需取得。长结果会返回引用列表，可用 evidence_id 作为 query 取得单条完整原文，ID 查询不展开关系。检索匹配原文、语义摘要和检索线索，并沿一层关系补充相关经历，仍遵守世界、类型、状态和数量限制；未命中时可以换用更具体的关键词，不能据此编造答案。

## 保存、更新与遗忘

`remember_game_memory` 的正文必须逐字保存玩家本次完整消息（最多 4000 字符），禁止截取子串。否定、条件、假设与指代保留在证据中。完整证据或删除预览超过结果预算时不会静默截断，需缩小查询或调整工具结果预算。助手回答、猜测、未执行的命令提案都不能作为玩家证据写入。更新同一事实、计划或经验时，应复用同一主题和世界范围；偏好通常采用跨世界范围。

`forget_game_memory` 先使用证据 ID 预览全部受影响记录并发出随机确认短语，此时没有删除。玩家随后发送完整确认短语，工具才凭一次性 token 删除。token 绑定玩家、证据 ID/集合和证据版本，五分钟有效；证据变化、重载或重启后需重新预览。`forget_place` 与 `remove_note` 使用相同授权和原子删除路径。删除时移除失去支持的摘要及关系；事实、计划与经验的同主题旧版本也会删除；若来源是地点或笔记，会同步删除原始地点或笔记，避免后续蒸馏重新生成。当前合成目标仍通过 `clear_goal` 清除。`forget_conversation` 只清理短期对话。

新工具只有在原子写入成功后才报告完成；文件损坏、未知版本、加载失败和队列拥堵时明确返回失败。旧版 v1/v2 记忆文件可读取，首次成功写入时升级为 v3。旧片段无法还原成完整对话。升级后不要降级到只支持 v1/v2 的旧插件。

## 配置

```yaml
panda:
  memory:
    enabled: true
    distillation: true
    distill_output_tokens: 4096
    recall_limit: 6
    context_chars: 1800
```

- `enabled`：游戏记忆与召回开关，独立于视觉和感知。关闭后已有数据保留。
- `distillation`：索引与后台语义摘要/关系开关；开启增加模型请求，关闭后仅检索原始证据。
- `distill_output_tokens`：蒸馏输出预算，512–8192 token，默认 4096，独立于聊天预算；每次生成量按此预算限制。
- `recall_limit`：每次检索最多返回 1–12 条记录。
- `context_chars`：自动附带的相关记忆预算，256–4000 字符。

独立只读工具可同时等待，`panda.agent.max_parallel_reads` 默认为 3，可设 1–8；写入、删除与未标记工具串行，结果保持调用顺序，Bukkit 访问始终在主线程。

同时加载的玩家数量沿用 `panda.perception.max_players`。可以通过 `panda.agent.disabled_skills: [game-memory]` 隐藏记忆工具。部署时已有的自定义 `prompts/system.md` 不会被覆盖；如果该文件经过定制，应合并新版的记忆检索规则。

相关记忆会作为上下文或工具结果发送给服主配置的模型服务商，详情见[安全与隐私](Privacy-and-Security.md)。
